# Task Report: RNP Branding

**Branch:** `automation/rnp-branding` (from `main`)
**Commit:** `8b0c3c7` — Rebrand container app to RNP with logo and brand palette

## Summary

The mail-extension container app is rebranded from "Ribose container" to
**RNP** and now carries RNP visual branding throughout: the real RNP logo as
the app icon, the logo's brand blue as the system accent color, and a
light/dark-aware brand palette for trust states. Target and scheme names are
unchanged, so all builds, CI, and release scripts keep working.

## What changed

### 1. App name → "RNP"

| Surface | Before | After |
|---|---|---|
| Menu bar app menu / About panel / Dock / Finder | "Ribose container" | "RNP" (via `CFBundleDisplayName` in `Swift-Rnp/MailExtensionsContainer/Info.plist`) |
| Window title | "OpenPGP Keys" | "RNP" (`title.keysManager`, all 11 languages; `WindowGroup("RNP")` in `MailExtensionsContainerApp.swift`) |
| Onboarding welcome | "Welcome to Swift-Rnp" | "Welcome to RNP" (all 11 languages in `Localizable.xcstrings`) |
| File header comments | `//  Ribose container` | `//  RNP` (6 files) |
| README | "Ribose container" app references | updated; scheme/target names kept where they refer to Xcode |
| `docs/SECURITY-MODEL.md` diagram | "Ribose app" | "RNP app" |

Menu items (About RNP, Quit RNP, etc.) are generated by macOS from the
bundle display name — no per-item strings needed changing.

### 2. RNP branding

- **App icon:** the `AppIcon.appiconset` was *empty* (no icon at all). The
  RNP logo from `icon.png` was measured (circle centers/radii, lens keyline,
  wordmark bbox, exact colors) and recreated at icon-set resolution on a
  macOS rounded tile by the new, committed generator
  `scripts/generate-app-icon.py` (Pillow; wordmark set in SF Compact
  Rounded). All 10 mac icon slots are filled; slots < 128 px use the
  circles-only mark since the wordmark would be illegible. This also fixed
  the onboarding hero (shows the app icon) and the default About panel.
- **Brand color:** `AccentColor.colorset` (previously unset) is now the
  logo's blue `#1A7BEC`. Because the UI consistently uses
  `Color.accentColor`, this one asset brands primary buttons, links,
  selection, toolbar glyphs, and onboarding accents app-wide.
- **`RnpBrand` palette** (`Sources/RnpMailUI/DesignSystem.swift`):
  `primary` `#1A7BEC` / `primaryDeep` `#0B54B8`, `highlight` `#FFDC4A`,
  `ink` `#2E3349`, plus dynamic trust colors — `verified` (teal-green from
  the logo family), `unverified` (orange), `critical` (red) — implemented
  with a macOS-12-compatible `NSColor` dynamic provider.
- **Applied:** `TrustPresentation` (verified/problem/unverified →
  brand green/red/orange), `RnpKeyAvatar` gradient (brand blue), revoked /
  expired / expires-soon badges in `KeysListView` and `KeyDetailView`, the
  "Mark as Verified" and copy-fingerprint button tints in `KeyDetailView`.
- **Consistency fix (polish):** the trust-conflict banner was orange while
  the same state was red in the trust card; it now uses `RnpBrand.critical`
  everywhere (matching the engine's `mapSignerTrust`, where problem →
  critical). Expiry banners distinguish expired (critical red) from
  expiring soon (warning orange).
- **`RnpLogoView`** (brand-blue gradient tile with `lock.shield.fill`) is
  the onboarding hero fallback when no app icon image is available (unit
  tests, SPM previews).

### 3. Not changed (per constraints)

- No logic changes in `MailSecurityEngine`, `KeyManager`, `TrustStore`,
  `KeyLifecycle`, `KeyServerClient`.
- Target names, scheme names, bundle IDs, app group, and the product/bundle
  file name (`Ribose container.app`) are untouched; all accessibility
  identifiers unchanged; no new dependencies.

## Caveat: `CFBundleName`

The task called for setting `CFBundleName` in `Info.plist`. This project
uses `GENERATE_INFOPLIST_FILE = YES`, under which Xcode **always derives
`CFBundleName` from `PRODUCT_NAME`** (`Ribose container`), ignoring both the
plist value and the (nonexistent) `INFOPLIST_KEY_CFBundleName` setting — an
attempted pbxproj change was reverted as ineffective. All user-visible name
surfaces (menu bar, Dock, Finder, About, window title) use
`CFBundleDisplayName = "RNP"`, so this is cosmetic-invisible in practice.
Fully renaming `CFBundleName` requires `PRODUCT_NAME = RNP`, which cascades
into the xcscheme `BuildableName`, `sandbox-audit.sh`, `release-direct.sh`,
`ci-release-dry-run.sh`, and two release workflows — deliberately left out
per the "don't break the build" constraint.
