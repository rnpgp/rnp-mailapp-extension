# 04 — Sparkle auto-update

**Priority**: P1
**Status**: shipped (Sparkle wired into project; appcast feed hosting pending)
**Effort**: S (code) + S (hosting)
**Dependencies**: signed + notarized DMG artifacts per release

## Problem

DMG-distributed apps have no update path. Users miss security patches,
ship-time bugs, and new features. By the time v0.9.7 ships, half the
v0.9.5 users haven't upgraded. Sparkle is the macOS standard; not having
it is "doesn't respect users' time".

## Goals / non-goals

**Goals**
- App checks for updates weekly
- Update path is signed-and-notarized DMG, transparent install
- User can disable auto-update check
- Channel: stable only (no beta/nightly for now)

**Non-goals**
- Delta updates (Sparkle 2 supports them but adds complexity)
- Background install without prompting (user always confirms)
- App Store version gets Sparkle — App Store version uses Apple's update
  mechanism, not Sparkle. Don't ship Sparkle in the AppStore config.

## Design

### Module layout

```
MailApp/MailExtensionsContainer/
└── Updater/
    ├── UpdaterConfiguration.swift   (channel, interval, enabled flag)
    └── SparkleBootstrap.swift       (wires SUEnableInstallerLauncherService on launch)
```

### Bootstrap

Sparkle 2 requires:

1. `SUEnableInstallerLauncherService` in Info.plist (set in build settings)
2. `SUFeedURL` in Info.plist pointing at the appcast XML
3. Code-sign the app with the Developer ID (already done in release)
4. Embed `SUAutoUpdateAppcast.plist`? No — just host the feed.

### Appcast feed

XML file hosted at `https://rnpgp.org/updates/appcast.xml`. Per release:

```xml
<rss version="2.0" xmlns:sparkle="http://www.andymatuschak.org/xml-namespaces/sparkle">
  <channel>
    <item>
      <title>Version 0.9.6</title>
      <sparkle:version>9060</sparkle:version>
      <sparkle:shortVersionString>0.9.6</sparkle:shortVersionString>
      <sparkle:edDSA>...signature...</sparkle:edDSA>
      <enclosure
        url="https://github.com/rnpgp/rnp-mailapp-extension/releases/download/v0.9.6/RNP-0.9.6.dmg"
        sparkle:edDSA="...signature..."
        length="10111908"
        type="application/octet-stream" />
    </item>
  </channel>
</rss>
```

The EdDSA signature is generated by `sign_update` from the Sparkle tools
against the DMG. CI step should generate this in `release.yml` after the
DMG is built and append to the appcast.

## Acceptance criteria

- [ ] Sparkle framework loads on app launch
- [ ] "Check for Updates…" menu item appears under the app menu
- [ ] User can disable update checks in Tools hub
- [ ] CI generates `appcast.xml` entry on each release
- [ ] `appcast.xml` is signed (EdDSA) for tamper detection
- [ ] End-to-end: old version → new release published → old version
      prompts within 1 hour
