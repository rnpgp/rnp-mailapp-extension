Security Model

What RNP protects

  • Files at rest. Encrypt any file with OpenPGP; only recipients with the matching secret key can decrypt.
  • Email content. RNP for Mail decrypts PGP/MIME messages in Apple Mail; signing confirms sender authenticity.
  • Key material. Secret keys live in the macOS Keychain-protected keyring inside the App Group container. Touch ID gates keyring unlock when enabled.

What RNP does NOT protect

  • Metadata. Email recipients, timestamps, and subject lines are visible to your mail server even when the body is encrypted.
  • Plaintext content you keep outside RNP. If you save a decrypted file to disk, RNP doesn't manage it afterwards.
  • Compromised endpoints. If your Mac is infected, the attacker sees plaintext the moment you decrypt.

Threat model

RNP defends against:

  • Network eavesdroppers (TLS is good, end-to-end is better)
  • Mail server operators who might be compelled to disclose content
  • File recipients forwarding or screenshotting content (we can't help here)

RNP does NOT defend against:

  • Malware on your Mac
  • Coerced passphrase disclosure (rubber-hose cryptanalysis)
  • Quantum adversaries with a working Cryptographically Relevant Quantum Computer (CRQC) — but our hybrid PQ keygen hedges this

Privacy

RNP has no telemetry. No analytics. No crash reporting. No "phone home". The only outbound network requests are:

  • WKD lookups when you fetch a recipient's key (https://openpgpkey.<their-domain>/...)
  • keys.openpgp.org when you search or upload a key (explicit; never automatic)
  • Autocrypt header exchange in your normal email flow (part of the protocol)
  • Sparkle update check against rnpgp.org/updates/appcast.xml (weekly, can be disabled)

That's it. Read the privacy policy.

Sandbox

RNP runs in the macOS App Sandbox. The entitlements are:

  • com.apple.security.app-sandbox — required
  • com.apple.security.application-groups — shared keyring between the host app and the Mail extension
  • com.apple.security.network.client — for WKD / keyservers / Autocrypt
  • com.apple.security.keychain-access-groups — for the Keychain-protected passphrase
  • com.apple.security.files.user-selected.read-write — for File Tools

Engine: librnp

The crypto engine is librnp — the same engine that powers Thunderbird's end-to-end encryption. It's actively maintained by Ribose Inc. and audited. RNP the app is a thin Swift wrapper around librnp; we add zero custom crypto.

Reporting a vulnerability

Email security@ribose.com with details. We respond within 48 hours. Please don't file security issues in the public GitHub tracker.
